A bridge connecting a WeChat ClawBot to Grok Bot routines

number5memeGitHub ↗Posted 2026-10-29Added 2026-10-29 22:37 UTC★ 1

What it does
The GitHub project grokbot-wechatclaw-bridge connects a WeChat ClawBot (Tencent iLink bot API) to any HTTP webhook or AI agent, with QR login, outbound-only long polling, owner protection, media support and self-recovery. It works with Grok Bot routines.

Steps / points from the source
  1. Outbound-only: no open port, public IP, domain, or TLS certificate; it runs behind NAT, on a laptop, or in a
  2. Any webhook: one JSON POST per accepted message (payload); payloads the webhook does not
  3. Safe replies: reply.sh --to '' --stdin with the text in a quoted heredoc, so reply text written by
  4. Self-recovering: reconnects forever with capped backoff, timeouts on every request, and recovery within about
  5. login.sh gets a QR code from iLink. You scan it with WeChat and confirm. The bot token is saved to state/ (mode 600).
  6. bin/bridge.js long-polls ilink/bot/getupdates. For each user message it applies dedupe and owner protection,
  7. Your agent replies with ./reply.sh --to '' --stdin (text in a quoted heredoc), or with --image,
  8. QR login (terminal QR code, PNG copy, or a link to open inside WeChat), including verification codes and QR refresh.

Risks and limits
  • Uses a browser or website login: the costliest kind of step, so prefer a connector where one exists
  • Scheduled runs keep consuming usage: start at a low frequency and raise it once it is stable
  • The author's result may not reproduce for you; the original post is the reference
