Steps / points from the source
  1. The website itself. Host it on Vercel. That is the default, even for a one-pager.
  2. API keys, database URLs, OAuth secrets. Anything that must not be in git.
  3. A static page can be regular HTML. Do not invent a framework for a landing page.
  4. If you need a real app (auth, API routes, a dashboard), use Next.js on Vercel.
  5. If that app uses React, follow React best practices (small components, no random client state, server where it belongs). Do not cargo-cult a design system o
  6. Never paste a live key into Grok, Slack, or a GitHub issue.
  7. Never commit .env. The repo can list the *names* (STRIPE_SECRET_KEY). The values live in Vercel.
  8. If an agent needs a secret, it reads the environment or a locked secret file, not the chat.
