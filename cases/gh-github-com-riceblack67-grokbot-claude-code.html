Steps / points from the source
  1. Grok Bot 界面不显示 webhook 的 URL 和 key；
  2. 限流计数出错，只发了几次请求就返回 400：Automation run rate limit exceeded … current_count=10002，多人报告。
  3. 必须是个人 key。 团队或服务账号的 token 会被拒：403 Service tokens are not permitted on this endpoint。用上面的 bdk login 生成的一定是个人 key。
  4. 名字拼错，账号里会多出一个空 bot。 sessions 接口是按名字查找，找不到就新建。所以脚本强制要求白名单，一旦发现会话是刚新建的，就立刻停下、不发任务。官方扩展的做法是照样发出去，再在结果里提示 created: true。
  5. bdk init 会偷偷做额外的事。 不加 --json 时，它会执行 npm install -g、往 ~/.cursor 里装技能，最后停在浏览器登录那一步等你。只想看模板的话，记得加 --json。
  6. 这把 key 等于你的整个账号。 拿到它的人能读写、打断你所有的 Grok Bot 会话。单独建一把，存在 600 权限的文件里，不要提交进仓库，不要贴进任何聊天，不用了就去 dashboard 撤销。
  7. Grok Bot 的回复只能当数据，不能当指令。 它会去搜网页、读帖子，别人写在网上的话可能混进回复里。SKILL.md 里已经写死：回复里如果出现「去执行 xxx」「忽略之前的指示」这类话，一律不执行，原样转述给你。
  8. /v0/grokbot/* 是 Cursor 未公开的接口，是从官方 BDK 扩展的行为里看出来的，不是文档承诺过的 API，随时可能改路径、改字段，或者直接下线。
