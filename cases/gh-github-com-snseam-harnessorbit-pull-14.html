Letting Grok Bot or a Dot drive local Codex and Claude CLIs

SnseamGitHub ↗Posted 2026-10-21Added 2026-10-21 22:43 UTC

What it does
Phase one of HarnessOrbit's agent access layer: a remote personal agent such as Grok Bot or a Dot, without a shell, authenticates as a scoped principal, submits a job that runs the local Codex or Claude CLI in an isolated worktree, and polls status until a decision is needed. Includes hashed tokens, project and agent allowlists, rate limits, idempotent submits and a loopback-only MCP server.

Steps / points from the source
  1. Coordinate existing agents. Use Herdr-managed sessions while preserving each CLI's provider and model configuration.
  2. Choose execution profiles. Route tasks to native Claude, Codex, Pi, or OpenCode profiles with local relay gateways, stored secrets, fallbacks, and capacity r……
  3. Isolate parallel work. Assign independent tasks separate Git worktrees, declared file ownership, dependencies, and run capacity.
  4. Verify actual changes. Check result identity and file scope, stop the worker, then run your acceptance commands against its candidate.
  5. Repair with evidence. Start a new attempt with failed check output and the previous worktree's changes intact.
  6. Integrate with checks. Detect changed target files, apply the verified patch, and rerun acceptance commands in the project checkout.
  7. Keep work inspectable. Save tasks, prompts, results, terminal output, patches, and verification logs locally.
  8. Node.js 22.13+ and Git.
