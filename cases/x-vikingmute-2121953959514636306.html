# 《Building always-on agents》要点：看似常驻，其实多数时间在休眠

Source: https://x.com/vikingmute/status/2121953959514636306

Author: vikingmute

作者总结文章《Building always-on agents》：always-on 代理大部分时间在休眠，事件到来后运行一次、保存状态再休眠。五个要素：Event Inbox（触发写入持久队列）、Timers（独立存储的跟进和日程）、Memory（独立于会话的持久存储）、Permissions、Outbox。循环为事件进 inbox → worker 新建或恢复 session → 加载记忆、在权限内行动、更新记忆 → 结果进 outbox → dispatcher 投递；计时器或用户回复再送回 inbox。作者认为这类似 Grok Bot 和 Muse 的设计蓝图。

What it does
The author summarizes the article "Building always-on agents": an always-on agent sleeps most of the time, runs once when an event arrives, saves state and sleeps again. Five parts: Event Inbox (every trigger writes to a durable queue), Timers (separately stored follow-ups and schedules), Memory (persistent storage independent of sessions), Permissions, and Outbox. The loop: event into inbox → worker starts a run and creates or resumes a session → agent loads memory, acts within permissions, updates memory → result goes to outbox → dispatcher delivers; timers or user replies send new events back to the inbox. The author sees it as a blueprint similar to Grok Bot and Muse.
