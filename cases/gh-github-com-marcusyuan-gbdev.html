Steps / points from the source
  1. Isolated worktrees — every worker gets its own Git worktree and branch; your checkout and target branch are untouched.
  2. Parallel lanes — a planner splits a goal into a task graph; independent tasks run in parallel lanes and merge into an integration branch.
  3. Bounded review/fix loops — reviewers and fixers iterate under explicit round, job, and time budgets; when the budget is used up, gbdev asks instead of looping.…
  4. Evidence, not vibes — checks you trust run at every merge; worker output is untrusted data; a missing review verdict is never treated as approval; read-only ……
  5. Explicit decisions — plans, failures, and conflicts become attention items that the controller answers with the current decision ID and an allowed action.
  6. No unreviewed merges, no pushes — finished work waits on an integration branch. Updating your local branch needs run land --confirm-user-approved, which the ……
  7. Node.js >= 24 and npm; Git >= 2.38; a Git repository with at least one commit.
  8. Codex CLI (codex) and/or Cursor agent (cursor-agent), installed and logged in by you. Provider access, models, and usage charges are your responsibility.
